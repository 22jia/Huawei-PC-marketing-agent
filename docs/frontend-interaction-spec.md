# 华为 PC 营销 Agent 前端设计与交互规范

## 1. 目标与边界

前端是供华为内部内容运营和门店营销人员使用的 Agent 工作台。它的职责是收集一条营销任务、清楚呈现 Agent 的运行过程与证据，并交付可人工编辑、复制和导出的内容。

它不是营销官网，也不是通用聊天机器人。首屏必须直接进入任务创建与结果查看，避免落地页、账号系统、历史任务中心等非初赛必要功能。

前端只能调用本项目的 `/api/v1` 接口。知识库状态显示本地 v7 索引；动态价格、库存和促销状态来自后端对 VMall 官方页面的核验。不得在浏览器端使用或暴露任何密钥。

## 2. 技术与视觉基线

- 技术栈：React、TypeScript、Vite、Ant Design 5。
- 组件优先级：优先使用 Ant Design 原生 `Form`、`Select`、`Steps`、`Alert`、`Tabs`、`Descriptions`、`List`、`Tag`、`Result`、`Drawer`、`Modal`、`Spin`、`Skeleton`、`Button`。
- 图标：使用 `@ant-design/icons`，不要手绘 SVG；图标按钮必须有 Tooltip。
- 布局：桌面优先，最大内容宽度 1440px，24px 页面边距，24px 栅格间距；卡片圆角不超过 8px。
- 色彩：使用 Ant Design 默认中性色和状态色。蓝色用于主操作，绿色表示通过，橙色表示需确认，红色表示阻断。不得以渐变、装饰性大图或大面积单色背景代替信息层级。
- 字号：页面标题 20px，区块标题 16px，正文字号 14px，辅助信息 12px。所有文字采用正常字距。

## 3. 页面信息架构

单页工作台由以下区域组成：

```text
Header
  项目名称 | 当前知识库状态 | 使用说明

Main
  左栏：创建营销任务
  右栏：Agent 运行过程与生成结果
```

### 3.1 Header

左侧显示“华为 PC 营销 Agent”和简短副标题“基于知识证据生成并核验营销内容”。右侧放置一个知识库状态 Tag：`本地库已加载`、`索引中` 或 `不可用`。动态信息另显示 VMall 来源链接和核验时间。

“使用说明”使用问号图标按钮，在 Drawer 中显示字段解释、风险规则和导出说明，不在页面常驻展示大段说明文字。

### 3.2 左栏：任务表单

桌面宽度下左栏固定为 400px，右栏占剩余空间；低于 960px 时上下堆叠，表单在前，结果在后。

使用 `Form` 的纵向布局。表单字段与 `POST /api/v1/generate` 保持一一对应：

| 视觉标签 | 字段 | 组件 | 规则 |
| --- | --- | --- | --- |
| 产品型号 | `model` | 带搜索的 Select 或 AutoComplete | 当前接口允许缺省；缺省时点击生成后展示 Agent 追问 |
| 目标受众 | `audience` | Input | 必填 |
| 宣传场景 | `scenario` | Select + 自定义输入 | 必填，例如开学季、移动办公、到店体验 |
| 内容目标 | `goal` | Select | 必填，例如种草、引导咨询、到店体验 |
| 投放平台 | `platform` | Select | 必填，值必须与接口契约一致 |
| 强调要求 | `requirements` | Select mode=tags | 可选，建议项：便携、屏幕、性能、互联、续航 |
| 图片数量 | `image_count` | InputNumber | 1-6，默认 3 |
| 包含价格信息 | `include_price` | Switch | 默认关闭；开启后仅允许使用有证据的价格 |

表单底部只有一个主按钮“生成营销内容”，配合 `RobotOutlined` 图标。提交时锁定表单主按钮，保留“重置”文字按钮。未填写必填项时由 Ant Design Form 在对应字段下展示错误，不能只弹出全局提示。

#### 平台枚举约束

当前 [接口约束.md](../接口约束.md) 仅允许 `xiaohongshu` 与 `wechat`。第一版前端必须按此实现，不得自行传入未约定值。

当后端将契约扩展为 `wechat_article` 与 `wechat_moments` 后，前端再将“微信内容”拆分为“公众号文章”和“门店朋友圈”。这两类内容的正文结构、图片数量和 CTA 必须不同，不能只改显示名称。

### 3.3 右栏：空状态

首次打开时显示简洁的 `Empty`：图标、文案“创建一条营销任务后，Agent 将检索证据、生成内容并完成核验”。不显示伪造的运行结果或示例产品参数。

## 4. Agent 运行过程

点击生成后，右栏立即切换到运行视图，顶部显示横向 `Steps`：

```text
任务理解 → 知识检索 → 平台策略 → 内容生成 → 事实与合规核验
```

前端默认使用 `POST /api/v1/generate` 的一次性响应。第一版可按本地状态依次显示步骤：请求开始时激活“任务理解”，响应成功后将所有步骤置为完成；若接口失败，则在对应步骤显示 error。后端未来提供流式事件时，前端可按事件实时更新，但不得阻塞初赛版本。

运行期间在结果区域使用 `Skeleton` 与“正在检索产品证据...”等短提示；不显示模型内部思维链，只显示用户可理解的动作状态。

## 5. 结果视图

成功响应后，右栏顶部显示结果操作栏：任务编号、生成时间、复制内容图标按钮、导出下拉按钮和“新建任务”按钮。

结果内容使用 `Tabs`，按以下顺序排列：

### 5.1 Tab：营销内容

- 使用可编辑的标题 Input 和正文 TextArea 呈现 `content.title`、`content.body`。
- 话题标签使用可编辑 Tag 列表呈现 `content.hashtags`。
- CTA 用单行 Input 呈现 `content.cta`。
- 编辑只影响浏览器内待导出版本。用户编辑后在操作栏显示“内容已修改，建议重新核验”，并提供“重新核验”按钮，调用 `POST /api/v1/validate`。

### 5.2 Tab：证据与配图

- `facts` 以紧凑 List 展示。每条显示事实内容、来源标题、置信度 Tag；没有来源的事实必须用 error 状态，且不能标为可发布。
- `images` 使用响应式图片网格展示缩略图、文件名、建议插入位置和“已核验/待确认”状态。
- 缩略图加载失败时显示图片占位符与来源文件名，不能静默替换为其他型号图片。
- 点击一条证据或图片，在 Drawer 中展示来源路径、匹配型号、更新时间和核验结论；不展示知识库内部 ID。

### 5.3 Tab：核验报告

按 `validation` 的五个维度展示：型号、事实、图片、平台、合规。每项使用 `Badge` 或 `Tag` 标记 `pass`、`warning`、`fail`。

`warnings` 为空时展示成功态 `Result`；存在 warning 时展示 `Alert type="warning"`；任一 fail 时展示 `Alert type="error"`，禁用“导出可发布稿”并提示人工处理阻断项。

## 6. 失败与追问状态

| 场景 | 前端行为 |
| --- | --- |
| 缺少型号 | 在右栏显示 Agent 追问卡片，将焦点放回“产品型号”；不生成虚构内容 |
| `KNOWLEDGE_BASE_UNAVAILABLE` | 显示错误 Alert 和“重试”按钮；不降级为无证据生成 |
| `NO_EVIDENCE_FOUND` | 显示未找到资料的结果，建议更换型号或补充场景；不使用相近型号替代 |
| `PRICE_NOT_VERIFIED` | 在价格相关内容处显示阻断错误，禁止导出可发布稿 |
| `COMPLIANCE_BLOCKED` | 展示阻断原因，允许修改后重新核验 |
| 网络或服务错误 | 全局 Message 提示简述，右栏保留表单输入与重试入口 |

所有错误文案使用后端返回的 `message` 作为主信息；前端不显示 API Key、Client ID、知识库内部 ID、原始堆栈或完整接口响应。

## 7. 复制与导出

- “复制内容”只复制标题、正文、话题和 CTA，不复制内部证据 ID 或调试信息。
- “导出”使用 Dropdown，支持 Markdown、TXT、JSON，对应 `POST /api/v1/export`。
- 导出前若核验为 `fail`，禁用导出按钮并用 Tooltip 说明“请先处理阻断项”。
- JSON 导出可以包含可追溯证据；Markdown/TXT 默认只输出可发布内容和必要的人工确认提示。

## 8. 接口对接状态

| 前端动作 | 接口 | 首版策略 |
| --- | --- | --- |
| 提交表单 | `POST /api/v1/generate` | 核心链路，必须对接 |
| 处理自然语言追问 | `POST /api/v1/analyze` | 可作为第二步增强 |
| 手动检索证据 | `POST /api/v1/knowledge/search` | 用于证据 Drawer 的增强能力 |
| 重新核验 | `POST /api/v1/validate` | 内容编辑后调用 |
| 导出 | `POST /api/v1/export` | 初赛 Demo 必须对接 |
| 平台规则加载 | `GET /api/v1/platforms` | 初始化时加载并缓存 |

在后端未完成前，前端使用固定 mock 响应开发。mock 的字段、状态和错误格式必须严格遵守 [接口约束.md](../接口约束.md)，并清楚标注为开发数据；Demo 录制前必须切换到真实接口。

## 9. 验收标准

1. 用户能在一个页面完成任务填写、生成、查看证据、查看核验、复制或导出。
2. 三种关键状态均可演示：成功、缺少型号追问、核验阻断。
3. 小红书与微信内容在结构、语气、图片建议和 CTA 上可明显区分。
4. 任一产品事实和图片都能查看来源与核验状态。
5. 所有屏幕宽度下文字不重叠、按钮不挤压，窄屏改为单栏。
6. 前端构建产物和源码中不含任何真实密钥。
