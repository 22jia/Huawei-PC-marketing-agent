# 华为 PC 营销证据闭环 Agent

## 一句话简介

面向华为内部内容运营与门店营销人员的场景化营销内容 Agent。它不是直接“写一篇软文”，而是先从本地《华为PC全板块深度知识库_v7》检索可追溯的产品事实和场景资料；涉及当前价格、库存或促销时，再从华为商城 VMall 补充动态信息，最后按目标人群、营销场景和投放渠道生成内容并完成核验。

## 1. 要解决的问题

华为 PC 的运营内容通常要同时满足四个条件：产品信息准确、素材型号正确、不同渠道表达合适、宣传表述可合规发布。通用大模型虽然能够快速生成文字，但容易产生以下问题：

- 将相近型号的参数、图片混用；
- 自行补全价格、补贴、销量、排名等无依据内容；
- 同一份文案只替换平台名称，不能适应小红书、公众号或门店私域；
- 运营人员无法判断一句卖点或一张图片来自哪里。

本作品将“知识检索、场景策划、内容生成、证据核验”连成闭环，目标是提高内容生产效率，同时把可发布性和可追溯性留在系统内。

## 2. 核心用户与使用场景

主要用户是华为内部内容运营、区域营销和门店营销人员。

典型任务：运营人员输入“为大学生开学季推广某型号 MateBook，在小红书发布并引导到店体验”。Agent 识别目标人群、场景、平台和内容目标，检索对应型号证据，输出带图文计划的内容与核验报告。门店人员也可以将同一型号切换为“商务通勤 + 门店朋友圈”，得到更短、更直接的内容结构和到店 CTA。

## 3. 差异化价值

### 3.1 场景策略驱动，而非参数拼接

系统先将任务标准化为“产品型号、目标人群、场景、内容目标、投放平台、强调要求”。随后依据场景策略决定：优先检索哪些资料、优先呈现哪些卖点、什么内容不可写。

例如：

| 任务 | 优先检索与表达 | 预期行动 |
| --- | --- | --- |
| 大学生 + 开学季 + 小红书 | 便携、屏幕、学习场景、跨设备协同 | 收藏、评论、到店体验 |
| 商务通勤 + 门店朋友圈 | 移动办公、连接能力、会议场景、到店服务 | 咨询、到店试用 |

这部分由项目的策略配置和任务分析模块决定，而非仅依赖一句“请按某平台风格写作”的提示词。

### 3.2 证据绑定与反幻觉发布闸门

每个进入正文的产品事实都必须关联至少一条知识库证据：来源文件、原文片段、适用型号和置信度。图片同样需要验证型号、来源和建议位置。

系统对生成内容执行确定性规则：

- 型号与目标型号不一致：阻断；
- 图片型号不一致或未核验：阻断；
- 出现价格、补贴、优惠，但没有价格证据：阻断；
- 无来源的产品参数：阻断；
- “最强”“第一”“全网”“唯一”等绝对化表述：告警或阻断；
- 用户手工编辑后：提示重新核验。

因此，系统输出的不只是文案，也包括“这句话为什么能写”“这张图为什么能用”的证据链。

### 3.3 平台内容编译，而非换一个语气词

平台策略以结构化配置控制标题规则、正文提纲、语气、图片数量、图片顺序、话题和 CTA。

| 渠道 | 内容结构 | 图片建议 | CTA |
| --- | --- | --- | --- |
| 小红书 | 场景痛点、体验叙事、已验证卖点、行动建议 | 4-6 张，场景与卖点结合 | 收藏、评论、到店体验 |
| 微信内容 | 目标人群、场景挑战、分段卖点、行动信息 | 1-3 张，信息表达优先 | 咨询、到店试用 |

后续可在接口契约中将微信内容进一步拆分为公众号文章和门店朋友圈，使正文长度、图片数和 CTA 产生可见差异。

## 4. Agent 工作流

```text
运营人员提交任务
  ↓
1. 任务理解：补齐或追问产品型号、受众、场景、目标、平台
  ↓
2. 证据检索：优先检索本地 v7 全板块知识库；动态商业字段按需访问 VMall 官方页面并记录核验时间
  ↓
3. 场景与平台策略：决定卖点优先级、正文结构、图文计划和禁止表达
  ↓
4. 内容生成：LLM 仅依据已验证事实生成结构化草稿
  ↓
5. 事实、图片与合规核验：规则校验 + 风险提示
  ↓
6. 工作台交付：查看、编辑、重新核验、复制、导出
```

本地 v7 知识库是 Agent 的静态事实与场景底座，VMall 是动态商业信息核验源；LLM 是语言理解与内容生成工具；任务分析、策略选择、证据账本和核验规则由本项目自研编排，构成作品的核心 Agent 能力。

## 5. 技术实现

### 5.1 系统架构

```text
React + Ant Design 工作台
  ↓ /api/v1
Node.js / TypeScript Agent 服务
  ├─ analyzeTask：任务结构化与缺字段追问
  ├─ localKnowledgeSearch / evidenceService：全板块检索、证据过滤
  ├─ vmallService：价格、库存、促销的官方动态核验
  ├─ buildPlatformStrategy：场景与平台策略编排
  ├─ llmClient / draftGenerator：基于事实账本生成内容
  └─ validatorService：事实、图片、价格与合规规则核验
  ↓
本地华为 PC 全板块知识库 + VMall 官方商城 + LLM API
```

### 5.2 关键数据对象

任务对象：

```ts
type MarketingTask = {
  model?: string;
  audience: string;
  scenario: string;
  goal: string;
  platform: "xiaohongshu" | "wechat";
  requirements: string[];
  imageCount: number;
  includePrice: boolean;
};
```

证据对象：

```ts
type Evidence = {
  evidenceId: string;
  model: string;
  claim: string;
  sourceTitle: string;
  sourcePath: string;
  sourceExcerpt: string;
  category: "spec" | "feature" | "scenario" | "image" | "price";
  confidence: "high" | "medium" | "low";
};
```

文案中的每个事实通过 `evidenceIds` 关联到证据；验证器据此决定能否导出为可发布稿。

### 5.3 接口和安全边界

前端仅调用项目后端 `/api/v1`，接口字段以 [接口约束.md](../接口约束.md) 为唯一标准。ima 和 LLM 凭证仅保存在服务端 `.env`，不进入前端构建产物、日志、截图或代码仓库。

前端交互规范见 [frontend-interaction-spec.md](./frontend-interaction-spec.md)。

## 6. Demo 展示设计

建议用“同一产品、两个任务”的对比证明差异化：

1. 输入：某 MateBook 型号、大学生、开学季、小红书、引导到店体验。
2. 展示 Agent 的任务理解、从 ima 命中的资料和图片、生成的种草内容、事实/图片/合规均通过的报告。
3. 保持型号不变，切换为商务通勤、微信内容、门店咨询。
4. 对比展示卖点排序、正文结构、图片建议和 CTA 的变化。
5. 制造一个可控风险，例如勾选“包含价格信息”但不给价格证据，展示系统阻断，而不是生成虚构优惠。

这五步能直观证明：系统既会“写”，又能在不同业务情境下“做决策”和“拒绝不可靠内容”。

## 7. 评审表达建议

可以用以下表述介绍作品：

> 我们没有把 ima 作为最终的文案工具，而是将它作为可信知识和素材检索层。我们的 Agent 自研了场景策略、平台编译、证据账本和发布前核验机制，让每一条内容都能回溯、能审查、能按渠道落地。

应避免仅强调“接入大模型”“多 Agent”或“自动生成文案”。评委更容易认可的是可展示的业务闭环：输入任务、检索证据、生成内容、拦截风险、交付可发布稿。

## 8. 当前工程状态与下一步

当前已完成：

- 项目目录、公共接口契约和协作边界；
- 官方 ima Skill 安装与服务端凭证配置；
- ima 知识库真实连通性验证；
- 前端 Ant Design 工作台规范；
- 基础 ima 客户端与证据服务；
- 客户成交辅助首版后端：客户描述规则洞察、需求追问、证据约束的方案候选、讲解脚本、异议回应与人工审核的 1/3/7 天跟进草稿。

下一步按优先级实现：

1. 扩充 `evidenceService`：按型号、场景与图片类型返回更细粒度的结构化证据；
2. 接入 LLM，使客户洞察和讲解脚本能理解更复杂的自由文本，同时保留规则与证据闸门；
3. 完成 `validatorService`：先覆盖型号、价格、图片、绝对化宣传四类高价值规则；
4. 完善 `POST /api/v1/generate`：串联内容生产最小闭环；
5. React + Ant Design 工作台：接入 `/api/v1/customer/assist` 与真实接口，录制 Demo。

## 9. 验收指标

- 每次生成都有任务编号、来源证据和核验报告；
- 无产品型号时系统追问，不擅自生成；
- 无证据的价格、参数和图片不能进入可发布稿；
- 同一型号在不同场景和渠道下的输出结构可明显区分；
- 前端不包含任何真实凭证；
- 完整 Demo 可在一台本地机器上复现。
