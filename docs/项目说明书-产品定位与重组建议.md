# PC Studio：产品定位与说明书重组建议

本稿用于先明确产品叙事，尚未替换根目录《项目说明书.docx》《项目说明书.pdf》。依据：现有说明书、赛题手册 v4、主办方初赛反馈及当前代码；功能存在不等于效果已被用户实验验证。

## 一、建议先确定的产品主线

**PC Studio 是面向华为门店员工的营销工作台：从一句不完整的想法出发，引导员工选产品、做出适合平台的图文，再承接顾客咨询与后续跟进。产品知识贯穿全过程，让表达有吸引力，也有真实依据。**

主标题可保留“PC Studio｜华为 PC 增长工作台”，副标题建议改为：

> 说清一个场景，做出一篇好内容，接住下一次顾客咨询。

优先服务门店导购与兼做内容运营的员工；店长属于辅助用户。说明书先讲“减少一线员工准备内容的工作量”，再讲成交辅助的延伸价值。“增长”表达产品目标，不代表已证明带来销量提升。

五项优势按用户使用顺序展开：**会引导 → 懂平台 → 会配图 → 查得到 → 能跟进**。“真实产品有依据”贯穿五项。

## 二、五项优势：先说用户价值，再解释实现

### 1. 不会写需求，也能开始：对话引导创作

员工不必先填一整套表单。知道型号时，围绕该产品创作；只知道“给经常出差的人推荐电脑”时，先按场景和产品资料推荐候选，解释理由，再由员工选择。

实现依据：任务规划模型结合历史消息与已确认任务解析新输入；更新需求；识别缺口；选择一个当前值得确认的问题并提供选项；场景产品检索提供候选。确认需求后进入策划与生成。会话状态与消息由服务端保存。

这项优势应称为“有上下文的引导式创作”，技术小节再解释“LLM 自主规划追问 + 任务状态管理”。避免宣称完全没有字段约束、永不重复追问或无限记忆。

展示方式：从“我想写一篇给出差办公人群看的内容，不知道选哪款”开始，展示候选理由、选择、平台确认与生成；对比传统必填表单。

### 2. 同一款电脑，在不同平台有不同讲法：平台软文 Skills

解决的不是单纯长短变化，而是阅读动机与内容角度：小红书侧重生活场景、共鸣和选购取舍；公众号围绕一个观点展开解释；朋友圈聚焦一个卖点和自然咨询邀请。

实现依据：根目录 `SKILL.md`、`platformStrategies.cjs` 与 `copywritingSkill.cjs` 共同提供表达规则和平台策略，并注入策划、写作及审稿阶段。场景习惯决定事实选择，平台策略决定展开方式。审核约束留在后台，正文通过引用角标承接事实来源，减少生硬免责声明。

展示方式：保持产品与受众相同，展示小红书和公众号两篇真实输出；标注开头角度、段落节奏、标题、配图与行动引导的具体差异。不能只列不同字数或标签。

边界：已有平台规则不等于每次产出都达到理想质量，更不等于已证明“爆款率”。差异与自然度应由成品证明。

### 3. 产品保持真实，配图适应场景：生图子 Agent

员工无需额外整理一整份视觉需求。主 Agent 把产品、受众、平台与图文计划交给图片模块，生成配合内容的场景视觉，减少找图和做图的工作。

实现依据：主流程准备产品素材并交付子 Agent；图片模块根据任务及配图目的选择风格，处理产品主体、生成背景、合成并保存图片。当前采用官方产品图主体与生成背景合成；透明素材保留蒙版，不透明素材通过配置的抠图服务处理。模型生成的是场景背景。超时、素材处理或生成失败时有官方素材回退路径。

展示方式：同时展示官方主体素材、生成场景和最终图文，说明图片为什么放在这个位置。

边界：不宣称生成图片能够证明性能、真实体验或绝对无失真；成品仍需检查边缘、多余物体与文字。配置图片上限不等于每次都能成功返回同样数量。

### 4. 学产品、写内容、查依据在同一处完成：集合工作台

新品速递帮助员工快速理解产品线定位与适用任务；知识库承接参数与功能查阅；生成内容中的引用角标可直接打开对应知识库条目，减少“写完后重新找依据”的操作。

实现依据：产品速览服务汇总本地产品资料并支持检索筛选；知识库浏览提供条目访问；正文引用编号由后端依据本次证据转换成知识库导航链接，而不是让模型自由编链接。客户工单、经营看板承接已记录的业务信息。

展示方式：先浏览一款产品，再生成内容，点击正文事实旁的角标返回对应条目，体现资料与创作相连。

边界：“新品速递”目前更准确的表述是“产品线重点速览”，不代表实时热销排行；看板反映录入系统的数据，不代表已接通平台曝光、获客归因或全店真实经营系统。

### 5. 内容之后还能接住咨询：成交助手

顾客咨询到来后，员工在同一对话入口描述客户用途、预算和顾虑，获得候选产品、推荐理由、讲解与异议回应，以及第 1、3、7 天的跟进草稿；需要持续跟进时，可继续建立客户工单。

实现依据：客户任务路由与洞察分析组织需求；产品资料支持推荐；价格服务读取具体型号、配置、日期及来源的官网价格快照，按预算筛选价格参考；门店价格规划另有规则与资格条件。跟进按阶段组织：第 1 天补齐影响选型的条件，第 3 天解决取舍并核实报价与权益，第 7 天确认决策和联系意愿，结合顾虑生成消息草稿。

展示方式：给出有明确预算与顾虑的客户描述，展示推荐原因、对应配置价格依据、不同日期的不同跟进重点，再建工单。

边界：不称“实时全网比价”或“自动成交”；不自动向客户发消息。比价按钮的完整交互仍需针对此前反馈复验，录屏应使用验证跑通的真实流程。

## 三、主办方关注什么，我们如何回应

手册第 3—5 页要求需求理解、资料检索、配图、生成与核验闭环，明确平台适配不能只是改变篇幅。第 9 页评分如下：

| 评分项 | 分值 | 说明书应展示的证据 |
| --- | ---: | --- |
| 业务场景理解 | 20 | 明确型号创作、场景推荐后创作两种路径；卖点如何回应使用习惯 |
| 产品事实准确性 | 20 | 型号与配置依据、正文引用角标、相近型号处理及冲突确认 |
| 图文生成与图片引用 | 15 | 成品图文、产品素材来源、图片说明和插入位置 |
| 平台适配与软文质量 | 15 | 同一任务换平台后的成品对比，具体说明角度与表达差异 |
| 自研 Agent 与提示词 | 15 | 系统如何规划追问、选择策略、调用工具及组织核验；附实际提示词 |
| 功能完成度与体验 | 10 | 连续运行录屏、可操作对话、修改导出、可追溯结果 |
| 合规与安全 | 5 | 不编造价格及承诺、冲突确认、凭证仅在服务端 |

主办方初赛反馈可概括为：**素材对应真实产品、内容吸引人、操作简单且减少员工工作量。** 因此，应围绕这三点组织论证；成交助手作为营销内容后的业务延伸，不能冲淡软文赛题主线。

材料口径需要准确：v4 第 5、9 页对 ima 来源及图片引用有明确要求，第 9 页写有非 ima 图片的扣分规则；后续反馈鼓励更换知识处理方式与自主生图。说明书应如实区分本地产品资料、官方素材来源、VMall 动态或快照信息、AI 背景，不把“官方来源”“本地检索”和“实时调用 ima”混为一谈。鼓励创新的反馈不宜自行解释为全部旧评分条款已经废止。

## 四、建议的正式说明书结构

1. **一页读懂 PC Studio**：谁在用、什么困难、一句话定位、五项优势、一个完整输出示例。
2. **从一句想法到一篇图文**：以门店员工的实际任务串起对话、选品、写作、配图与引用。
3. **五项产品优势**：每项固定按“用户困难 → 使用前后变化 → 页面/成品证据 → 具体实现 → 当前边界”展开。
4. **真实运行结果**：至少三组，覆盖两类业务场景与两个平台；明确输入、过程、输出、资料和图片来源。
5. **自研 Agent 如何支撑上述体验**：用一张架构图及阶段职责解释编排、Skills、子 Agent、会话与核验。详细字段和提示词放附录。
6. **赛题回应与验证**：评分映射、真实已测结果、尚未验证内容。
7. **部署、来源与已知限制**：实际启动步骤、依赖、数据来源、公开链接及演示版本。

建议三组案例：大学新生开学季小红书；商务差旅公众号（从场景出发选品）；同产品改写门店朋友圈。另补成交辅助作为扩展案例，不代替软文案例数量。手册第 8 页要求不少于三组结果、至少两类场景与两个平台，并提供真实运行视频。

## 五、原稿需要具体调整的地方

- 把泛化的“四层能力主线”改成可感知的五项优势与真实用户旅程。
- 把生图子 Agent、平台 Skills、引用跳转、对话式追问放到前部；目前原稿未充分表达这些特色。
- 删除或改写仍描述多入口、先填必要字段的旧使用步骤，匹配当前统一对话入口。
- “调用知识库：https://www.vmall.com/”应改为知识与素材来源说明；商城、知识库及检索方式分别说明。
- “正式说明书应结合实际代码补充”等编辑提示不能进入提交版；空白测试结论与链接占位需要真实补全。
- “准确率不低于 95%”若无测评，不作为已实现效果；“可衡量”若保留，限于已录入工单数据的统计。
- 压缩重复的背景、目标和能力表格，把篇幅留给成品对比、真实运行证据与用户操作变化。

待对齐的核心选择只有一个：**以“对话式营销图文创作”为主线，以“成交跟进”为延伸；五项优势共同证明操作省力、内容适配、产品真实。**
