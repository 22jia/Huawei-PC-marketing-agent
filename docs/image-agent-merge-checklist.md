# 生图 Agent 合并与演示清单

## 最小范围

知识库已有素材的 Huawei PC 型号，正式工作台 5173；一次交付 1 张 AI 背景＋知识库官方透明 PNG 主体合成图。支持商业宣传海报和日常生活照。其余配图保留官方原图，分别标注来源。仅当具体型号素材索引精确匹配且 PNG 实际含透明像素时生成；否则停止并保留原图，不借用相似型号素材。当前不承诺重绘主体、改变视角或真实图像编辑。

## 接入契约

- 主入口：`taskAgent.generate` → `integrateImages` → `generateCreativeImages`。
- 上游传入：`task / evidence / assets / platform / strategy.image_plan`。
- 图片模块使用任务的精确型号、目标、场景、平台、受众；在该型号自己的图片索引中检查透明 PNG，并按图片说明筛配色和视角。目标含“海报”优先商业海报；含“日常／生活照／氛围照”优先日常。
- 返回：图片 URL、`generated: true`、`generation_mode: ai_background_composition`、真实 `source_product_image` 和官方来源，保留配图槽位。
- 图片失败：返回 `imageGeneration: failed` 和警告，保留官方图。此时文案成功不代表 AI 生图成功。
- 图片模块可独立调用，不依赖文字模型；目前工作台已有主流程在文字审稿后调用图片模块，这是主应用现有编排，不是图片模块的强制依赖。

## 两条演示用例

共同字段：平台小红书；型号 HUAWEI MateBook 14（鸿蒙版）；受众大学生；场景“图书馆自习，整理课程报告”。

1. 内容目标“生成一张高级商业产品宣传海报，并配简短种草文案”。
2. 内容目标“生成一张图书馆日常生活照，搭配简短种草文案”。

点击“开始创作”，完整流程可能需要 1–3 分钟，不连续重复点击。验收：图片生成阶段成功、正文图片可加载、图片下方显示 AI 生成合成图；普通官方图片不能冒充成功。

## 本地运行

项目根目录 `shencangblue-git`，仅需后端和前端两个服务，已有运行实例无需再开。

```sh
node --env-file=.env services/api/src/server.cjs
```

另一个终端：

```sh
npm run dev --prefix apps/web
```

工作台 http://127.0.0.1:5173/，API http://127.0.0.1:3000/health。4321 是独立试验台，不是演示必需服务。配置来自根目录 `.env`，不是 `.env.image-playground`。

## 合并前必做

- 合并完整 imageAgent 模块、主流程接入、生成资源路由、前端已有 AI 标识与本地 URL 放行，不能只拷贝试验台。
- 包含 `services/api/package.json`、`package-lock.json` 和海报 Logo 文件 `assets-huawei-icon.png`。
- 合并环境安装服务端依赖：`npm ci --prefix services/api`。
- 安全配置 `.env.example` 可提交，`.env`、`.env.image-playground`、Key 和本地生成缓存不提交。
- 合并目标环境配置图片 Key、模型、超时，重启后端一次；重新跑上面两条用例。
- 先确认和同学的 `taskAgent.cjs` 没有覆盖冲突。当前图片入口对上游规划只替换一个已选槽位，不修改文案。
