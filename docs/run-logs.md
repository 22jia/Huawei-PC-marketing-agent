# 运行日志与失败追踪

创作页面右上角“运行日志”可查看最近运行、筛选失败、按 `req_` 编号查询。发生错误时，对话会显示本次编号。每轮生成、审稿与修稿记录都保留；失败草稿仅供排查，不属于可交付内容。

## 本地文件与查询接口

- 默认目录：项目根目录 `data/run-logs/`，可通过服务进程环境变量 `AGENT_LOG_DIR` 调整。
- 每个请求一个 `<request_id>.jsonl` 文件，阶段完成即追加，服务重启后仍可读取。中断运行保留已写入事件，显示“执行中 / 未结束”。
- `GET /api/v1/runs?status=failed&limit=50`：失败摘要列表；省略 status 返回全部，limit 最大 100。
- `GET /api/v1/runs/<request_id>`：阶段详情。

记录所有非 GET 请求；查询日志本身不新增记录。API 请求、结果和错误使用同一个编号。模型调用记录输入、响应、模型、耗时、用量及上游返回的请求编号。营销流程另有检索、策划、草稿、审稿、修稿事件。grounding 事件记录具体规则、命中文字、原句与参与比较的证据路径，保留现有核验策略。

业务核验拦截返回 HTTP 422，模型服务异常返回 502，其余未分类异常返回 500。请求失败仍会写入 request_error 与 run 结束记录；磁盘写入异常以 TRACE_WRITE_FAILED 输出到标准错误，避免悄悄丢失记录。

## 数据边界

日志会保留任务正文、历史对话和各轮草稿，仅用于本地诊断。API Key、Authorization 等凭据字段以及进程环境中的密钥值会过滤；单个超长字符串在 240000 字符处标记截断。目录已加入 .gitignore。当前不自动清理历史文件，可按需归档或删除旧文件；删除文件后对应运行无法再查询。此查看接口随本地服务仅监听 127.0.0.1；部署到共享环境前应添加权限与留存策略。

旧版未记录的失败无法追溯。自动化测试使用临时目录和模拟模型，不冒充真实用户的原始失败。

## 修稿停止策略

`repair_decision` 事件记录继续修稿或停止的理由。生成与两类核验共用一个策略：

- 同一失败草稿再次出现（忽略空白、对象字段顺序与空字段）时提前停止。
- 同一组核验问题累计出现三次时停止。问题签名基于规则和命中词；语义相同但措辞不同的问题仍可能识别不到，因此必须同时保留硬预算。
- `AGENT_MAX_REVISIONS` 默认 4，范围 0–8，指首次生成之后允许的修改次数。该默认值是成本保护配置，未经成功率实验验证，不代表四轮最佳。
- `AGENT_REPAIR_TIMEOUT_MS` 默认 180000，指开始生成草稿起，失败一轮之后是否允许继续修稿的时间预算。它不取消已经发出的模型调用，也不包含此前检索与策划的耗时；每次模型请求仍有自己的超时。

达到任何停止条件仍不交付失败草稿。错误详情保留最终命中、修稿历史和停止原因。确定性核验的精确命中内容与证据路径会传给下一轮修稿，而非只传通用错误提示。该策略不改变事实核验规则本身，单位表达、否定语境等误判仍需另外修正规则。


## 用户决策与需求检查
策划必须返回requirement_issues数组，逐项检查requirements里的事实性要求。conflict表示同型号、配置和条件下原文明示矛盾，至少附一条已校验引文；unsupported仅表示当前检索未支持。服务端校验原要求确实属于用户任务，并把quote_id解析为原文，禁止编造引文后向用户追问。
有问题时返回needs_confirmation与decision_required（原要求、原因、来源、选项），记录user_decision_required事件。策划、写作、审稿均可触发；写作或审稿发现冲突后不继续修稿，也不交付未通过草稿。日志列表切换全部运行即可查看，此状态不是接口失败。用户在同一对话明确删除或修改要求后，任务规划更新字段，重新检索检查；仅回复“继续”保留原要求。
这不是持久化任务状态机：续接依赖前端传回的最近对话与当前表单。新提供的材料仍需进入现有可检索来源并经核验，用户回复不是证据。冲突的语义识别仍依赖模型；代码只校验结构、原要求和引用真实性，不能保证语义判断永不误判。当前新增的逐项检查覆盖requirements；价格、素材缺口和底层规则误判仍沿各自现有处理路径。

策划格式检查会记录 schema_validation 事件，包含字段、期望格式和实际值，并将这些具体问题传给一次格式修复调用。evidence_ids 中误填的引文编号，仅在该编号确实存在于本次 quote_candidates 时转换为所属资料编号并去重，记录 schema_normalization；不存在的编号继续拦截，绝不猜测来源。


## Studio 实时阶段进度

Studio 通过 `POST /api/v1/generate` 携带 `Accept: text/event-stream` 请求SSE；不带该头的旧客户端仍收到普通JSON。流依次包含progress、每10秒的heartbeat，以及唯一最终result。SSE连接建成后HTTP为200，后续业务失败通过result中的status:error与code表达，不再改HTTP状态；普通JSON路径保留原错误状态码。

progress只包含实际执行阶段、开始/完成/失败、耗时、修稿轮次和request_id，不传模型提示词、内部推理或未经核验草稿。页面显示需求理解、检索、策划、写稿、事实核验、审稿及修稿过程，并保留本次运行编号，右上角可进入日志查询。此版本为阶段进度流，正文仍在全部核验完成后一次交付。

对话适配器使用AsyncGenerator持续发布消息：请求开始即在助手气泡显示连接状态，随后用实际阶段和心跳耗时更新同一气泡，最终回复或错误替换进度文字。仅更新外层React进度面板、等待Promise结束才返回正文，会导致助手气泡在执行期间为空。取消后留下的进度消息带studio_progress标记，不进入下一轮模型对话历史。回归测试覆盖最终结果尚未到达时气泡已获得阶段快照；浏览器验收通过独立模拟SSE服务验证实际页面显示及最终替换，不调用真实模型。

点击停止或关闭流连接会中止当前模型请求，并阻止后续阶段；已启动的本地同步检索不能被强行打断，阶段返回后检查取消信号。已写入日志保留，正常捕获的取消以RUN_CANCELLED记为失败结束。网络断流没有最终result时，前端明确提示未收到最终结果，不视作生成成功。

公共提示词只保留事实、规则优先级与交互边界，策划/写作/审稿各自附加阶段任务。写作和审稿支持经原要求及原文校验的ask_user出口；代码不能证明模型对矛盾的语义理解必然准确。当前模型仍由LLM_MODEL配置，没有自动切换或完成模型优劣评测。

## 模型请求超时

LLM_TIMEOUT_MS 控制单次模型请求（含响应体）的等待上限，默认 120000 毫秒，最高 300000 毫秒；调用方可显式传 timeoutMs。provider_request 记录模型与预算，provider_connection 记录实际耗时和底层异常。LLM_TIMEOUT 表示等待超时，LLM_CONNECTION_FAILED 表示网络连接失败，RUN_CANCELLED 表示主动取消；读取响应体时超时也不再误报 JSON 格式错误。超时不会自动重试或切换模型。

成交话术生成只加载 customer-conversion skill 中的对客表达、分阶段跟进交付和事实边界章节；产品证据保留一次原文与来源，省略该阶段不使用的重复引文候选。
