# 图文软文 Agent：当前实现与验收

交付物是可阅读、可改稿的图文软文。六个平台共用事实检索，但分别配置内容结构、语气、目标篇幅、互动方式及配图建议，抖音输出图文轮播，B站输出专栏图文，不再默认生成视频脚本。

## 执行链路

1. 大模型判断生成、改稿或问答，提取最新需求。
2. 先检索本地产品事实，按需补充官方商城信息，型号版本不明确先追问。
3. 大模型规划场景矛盾、文章角度、提纲、证据编号与配图。素材候选来自本次检索中具体型号的产品目录和官方图片索引。
4. 大模型根据平台策略和证据写完整软文。正文、行动邀请分别返回，避免重复。
5. 基础规则拦截无证据参数和价格；大模型检查平台风格、场景具体性、证据限制、图注与最新修改要求。
6. 事实规则拦截时不直接终止：把具体失败原因、上一版文案和删除无依据卖点的指令交给模型重新生成，再执行事实检查和审稿。规则修复与审稿共用最多两轮自动修改预算；连续两次模型审稿不通过则终止。不跳过检查，也不用模板顶替。
7. 对话按“场景判断、知识库依据、图文软文、核验结果”展示 Markdown 图文，支持继续追问、改稿、查看策划；复制只取文章，下载 MD 包含完整交付。

`llm.stages` 记录 analysis / strategy / generation / review，以及可选 revision / review，均为真实调用元数据。不存在模板模式或跳过审稿的生产配置。

## 新增响应字段

- `content_strategy`：angle、reader_tension、platform_reason、outline、evidence_ids、fact_points、conflicts、image_plan、asset_gap。
- `scene_judgment`：人群、场景、购买阶段、主要问题、目标、平台及切入点。
- `images`：服务端解析素材ID得到的文件名、本地路径、图片地址、来源页、尺寸、图注、用途、位置和核验状态，不接受模型自编链接。
- `editorial_review`：passed、platform_fit、issues、revision_instructions、revision_count。
- `content_strategy.fact_points` 用 evidence_id / quote_id 指向本次资料；服务端从原文索引解析 quote，避免模型跳过中间条件拼接“引用”。引用编号不存在会停止生成。
- 旧字段 content / facts / validation / task 保持兼容。问答分支不进入图文生成和审稿。

## 已知边界

本地 v7 知识库按参赛方与主办方确认的口径作为认可资料来源，无需在线调用 ima。缺少产品资料、发现资料冲突或没有同型号图片时，停止交付并明确待补充或待核对项。

图片使用官方素材并按索引匹配，未做视觉模型核验，也没有生成情景照片、烧录文字或自动裁切。3:4、16:9是排版建议。图片不能证明软件兼容或性能；发布前仍需核对型号、画面和使用权。MD引用本地服务图片链接，服务停止后链接不可用，不是离线素材包。

审稿是模型判断加有限的规则校验，不能替代人工事实核对，也不保证文案转化率。当前模型配置、来源质量都会影响成稿质量。会话在页面内保留，刷新页面不保证恢复。

## 验证

- `node --test tests/*.test.cjs`：素材版本隔离、非法图片ID、审稿重写上限、事实拦截、会话衔接。
- `node scripts/smoke-illustrated-copy.cjs`：真实模型分别创作小红书与公众号图文，检查成稿、审稿及实际图片HTTP响应。
- `node scripts/smoke-agent-conversation.cjs`：真实模型澄清→创作→提问→改稿。
